# Attendance shop calendar and paid leave review

The attendance import preview shows weekly shop closures in blue, special closed dates in purple, selected paid personal leave in amber, and unchecked working-day absences in red. White identifies other attendance/future rows. Each row includes a short note as well as its colour. A colour key and unpaid-leave instructions appear inside the import review itself as well as beside the shop calendar. Saved attendance rows also identify weekly and special closures.

Weekly shop closures come from the unchecked **Weekly Work Days** in Salary Settings. Leave & Holiday Settings shows the same closed weekdays. Saving either settings screen updates the other representation atomically. Existing weekly-leave settings are used when no weekly work-day list has been configured; the legacy fallback remains Friday. An explicitly empty work-day list means every weekday is closed.

In Attendance → **Shop closed days**, choose a month, a date within that month, and a closure name/reason, then use **Add special closed day**. The date is stored in the shared holiday calendar as an active Company holiday with leave enabled. The preview batch remains selected after saving. Existing enabled holidays are also treated as special closures. Salary-settings permission is required to add or manage closed days; attendance users can view the calendar and review leave selections.

A **Paid leave** checkbox appears immediately before each import row’s date. A working day dated today or earlier with both punches missing is checked automatically. Shop closures and rows with either punch are unchecked and disabled. Future dates are not automatically checked; an empty future working day is skipped unless paid leave is explicitly selected. No rows are invented for dates missing from the uploaded file.

The operator can uncheck an empty working day to retain normal absence deductions. Checked rows import as **Paid Leave**, with no absence deduction or worked minutes. Shop-closed days import as calendar leave, separately from personal leave. Actual work on a closed day remains worked attendance, with its original punches, rather than becoming personal leave. Adding/changing a punch or changing the date refreshes the checkbox and colour. Technician mappings, identity protection and automatic checkout behavior are retained.

The backend recalculates each submitted date’s closure status; submitting a checked box cannot convert a closed day or an actual punch into paid personal leave. A calendar snapshot protects the review from changes to weekly settings, holidays or the review date. If that snapshot changes, the user must reload and review before confirming. The preview form wraps all row inputs so checkbox values and edited dates/times are submitted together. Existing rows are updated (the preview labels these **Will Update**), while finalized/paid payroll periods remain locked.

This feature uses the existing salary settings, holiday dates and attendance-import JSON fields. No database migration or automatic rewrite of existing attendance/payroll is required. Changes are posted only when the user saves a calendar setting or confirms an import. Local verification uses the isolated testing database; no live server data was accessed or changed.

# Correct accidental work on a closed day

Closed-day attendance rows with punches or worked hours have a **Mark not worked** action. It opens the edit form with **Not worked · shop closed / holiday** selected. Enter an edit reason and save. The correction clears punches, worked hours, OT, automatic checkout and manual amount overrides, while preserving the note and recording the original punches and status in the audit log.

Not Worked retains the date's weekly/holiday metadata. It contributes no worked day, approved personal leave, absence deduction or OT. Single-row, bulk and draft salary recalculation preserve this explicit choice. On a normal working date, choose Absent, Paid Leave or No Pay Leave instead; Not Worked is limited to configured shop-closed or holiday dates.

Genuine work remains supported: choose Present and enter the actual times to restore worked-on-leave attendance. Editing and recalculating an existing Worked on Leave Day now retains its worked-on-leave flag. Finalized, partially paid and paid salary attendance remains locked under the existing rules. Existing salary drafts must be explicitly refreshed to reflect attendance corrections.

No migration is needed for this attendance change. Local verification: 78 selected attendance, payroll and draft-detail cases passed (466 assertions), including weekly/special closures, correction reasons, recalculation persistence, restoring real work and salary locks. Live data was not changed.
